## 1. 목적

`krun-prescreening-report` 스킬(Claude 대화형)을 Python 엔진으로 구현해, PC 앱에서
**IR 자료(PPT/PDF/이미지)를 파일 선택하면 예비검토보고서가 생성되어 Obsidian에 저장**되게 한다.

기존 흐름과 동일한 산출:
- 파일명 `{회사명}_YYYYMMDD_예비검토보고서.md`
- 저장 ① `00_Inbox/companies` (필수 — `company_property_sync` 자동화가 스캔)
- 저장 ② `config.local.yaml`의 `paths.obsidian_save` (이중 저장)

## 4. 설계

### 4-1. 엔진 배치 — SSOT 유지, 런타임 로드

`engine/`·`scripts/`는 **`Prescreening_Report`에 그대로 둔다**(단일 원본).
앱은 설정에 등록된 경로에서 **런타임 import**한다.

**이유**: 앱에 복사하면 스킬 개선 시 두 벌이 갈라진다(krun-fms v5.43.2에서 겪은 유형의 사고).
런타임 로드면 스킬을 고쳐도 **exe 재빌드 없이** 반영된다.

- 설정 탭에 `예비검토 엔진 경로` 항목 (기본값 `C:/Users/anton/Documents/Claude AI_Personal/Prescreening_Report`)
- 경로가 없으면 탭에 **"엔진 미설치" 안내를 표시하고 기능을 잠근다** (조용히 실패하지 않음)
- **태윤 배포본(`build_taeyun.bat`)에는 이 탭을 노출하지 않는다** — 내부 전용 기능

### 4-2. LLM 추상화 (Claude 전환 대비)

`engine/llm.py` 신설:

```
judge(task, prompt, provider="gemini")   # provider: gemini | claude
```

- **추출·조사**(IR 판독, 그라운딩)는 Gemini 고정 — Vision 페이지 수·비용 이점
- **판단**(§1 펀드적합성, §9 DD 체크리스트, §10 투자의견)만 provider 교체 가능
- 설정 탭 드롭다운 `판단 엔진: Gemini(기본) / Claude`
- 앱에 이미 `anthropic` SDK와 Claude API 키 설정이 있어 배선 비용이 낮다

### 4-3. PPTX Vision 보강 (필수)

**현재 결함**: `ir_reader._load_pptx()`는 텍스트만 추출하고 Vision 미지원.
IR PPT는 도표·그래프 안에 숫자가 있어 **이대로면 과거 KQC 재무 누락 사고가 재발한다.**

**해결**: PowerPoint COM(**설치 확인됨 — v16.0**)으로 슬라이드 → PNG 렌더 → Gemini Vision 전달.
- COM 실패 시 텍스트 폴백하되 **UI·보고서·로그에 "이미지 슬라이드 판독 실패" 경고를 명시**한다.
  (실패를 성공으로 보고하지 않는다 — 글로벌 「거짓보고 금지」 원칙)

### 4-4. 앱 탭 UI

새 탭 **`📑 예비검토보고서`** (기존 3탭 → 4탭)

```
회사명           [___________]
IR 자료          [파일 선택…] (다중, pdf/pptx/png/jpg)
                 └ 선택된 파일 목록 + 총 페이지 수
옵션             ☑ 외부조사(DART·그라운딩)  ☑ 검증 파이프라인
                 판단 엔진: [Gemini ▾]
                 [ 보고서 생성 ]
─────────────────────────────
진행 로그 (단계별 실시간 출력)
─────────────────────────────
완료 → 미리보기 + 저장 경로 2곳 표시 + [폴더 열기]
```

- 파이프라인이 **수 분~십수 분** 소요 → 별도 스레드 + 진행 로그(기존 STT 진행 UI 패턴 재사용)
- 실패 시 **어느 단계에서 왜 실패했는지** 그대로 노출

### 4-5. 파이프라인 연결

```
[앱] 파일선택
  → ir_reader.load()          IR 전수 로드 + 키워드 소재 확정
  → extractor.extract()       Gemini 4그룹 판독
  → research.*()              DART + 그라운딩 (혁신의숲은 폴백)
  → run_pipeline.py           A 조사 → B 인용게이트 → C 재무계산 → D 독립비판
  → build_md_report.py        MD 렌더 (기존 47KB 자산 재사용)
  → Obsidian 이중 저장
```

기존 `scripts/` 자산은 **재구현하지 않고 그대로 호출**한다.

바꾸면 기존 녹음·회의록·Drive 연동이 끊긴다.

## 6. 리스크 · 사전 고지

1. **품질 등가 아님** — 스킬은 Claude 대화형 판단이다. 전량 Gemini 자동화는
   §9 DD 체크리스트·§10 투자의견의 깊이가 스킬보다 낮다. **초안 생성기**로 보고,
   심사역 검수를 전제한다. (품질 미흡 시 4-2 구조로 Claude 전환)
2. **혁신의숲 기업조회 미확정** — 엔드포인트 탐색 전까지 그라운딩 폴백(THE VC·딜사이트 등)으로 동작.
3. **엔진 미검증** — 오늘 작성된 코드가 아직 한 번도 실행되지 않았다. 1번 작업에서 실패가 나올 수 있다.
4. **소요 시간·비용** — 보고서 1건당 수 분~십수 분, Gemini API 호출 다수.
5. **PowerPoint COM 의존** — PPT Vision은 MS Office 설치 PC에서만 완전 동작.

## 8. 실행 결과 — 설계 변경 (2026-07-19)

### 8-1. 가장 큰 판단 착오와 수정

**기획 당시 「스킬을 Python으로 재구현」만 검토하고, 「스킬 원본을 실행」은 검토하지 않았다.**
사용자 질문("스킬을 그대로 넣을 수는 없나?")으로 드러났고, 실측으로 확인했다.

| 방식 | 총 분량 | 인용 도메인 | 비용 |
|------|---------|------------|------|
| 엔진(Python) + Gemini | 43,927자 (66%) | **2종**(vertexaisearch 리다이렉트) | 무료 |
| 엔진 + Claude API | 48,653자 (73%) | 2종 | API 크레딧 |
| 엔진 + narrative 보강 | 55,935자 (84%) | 2종 | API 크레딧 |
| **스킬 원본 실행** | **66,577자 (100%)** | **17종**(실제 출처) | Claude 구독 |

엔진이 84%에서 막힌 근본 원인은 서술력이 아니라 **조사 수단**이었다.
엔진은 Gemini 그라운딩 요약만 받아 원문을 못 보지만, 스킬은 `WebSearch`·`WebFetch`로
실제 페이지(경쟁사 홈페이지 포함)를 열어 읽는다.

### 8-2. 확정 구조 — 2모드

앱 탭에서 선택한다. **둘 다 Claude 구독 한도 안에서 동작**한다(API 크레딧 불필요).

| 모드 | 구현 | 품질 | 소요 | 전제 |
|------|------|------|------|------|
| **스킬 모드**(기본) | `claude --print`로 스킬 원본 실행 | 100% | 7~40분 | Claude Code 설치 |
| **엔진 모드** | Python 엔진, 판단은 Gemini 또는 `claude` CLI | 66~84% | 5~15분 | 없음(Gemini만으로 동작) |

- 엔진 모드의 Claude 판단도 **CLI 경유**로 바꿔 API 크레딧을 쓰지 않는다
  (`PRESCREEN_CLAUDE_VIA=api` 로만 API 방식 사용 가능)
- Claude Code 미설치 시 스킬 모드는 **선택 자체를 차단**하고 안내한다(조용한 폴백 금지)

### 8-3. 미팅 중 사용 시나리오 반영

녹음과 보고서 생성을 동시에 돌릴 수 있으나, **녹음은 복구 불가**이므로
녹음 중 실행 시 경고 다이얼로그를 띄워 사용자가 그 자리에서 판단하게 한다.

### 8-4. 엔진(Python)을 남기는 이유

스킬 모드가 상위 호환이지만 엔진도 유지한다.
- Claude Code 없는 PC(배포본)에서 유일한 수단
- Gemini 무료 — 1차 스크리닝으로 여러 건 훑을 때
- 엔진 개발 중 만든 자산(감사보고서 판독·밸류에이션 역산·PPT 차트 추출)은 독립적 가치가 있다

### 8-5. 작업 중 잡은 결함 (모두 실측·수정 완료)

| # | 결함 | 영향 |
|---|------|------|
